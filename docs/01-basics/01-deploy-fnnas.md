# 第1章 在飞牛NAS上部署OpenClaw

> 本章目标：让你从0开始，在飞牛NAS上把OpenClaw跑起来

## 1.1 准备工作

在动手之前，确认你有这些东西：

- **一台飞牛NAS**（装了飞牛OS，系统版本无所谓，都支持）
- **能上网**（废话😂）
- **浏览器**（Chrome/Edge/Firefox 随便）

那咱们开始。

### 第一步：进到NAS的管理界面

打开浏览器，输入你飞牛NAS的IP地址。比如你NAS的内网IP是 `192.168.1.100`，那就在地址栏输入：

```
http://192.168.1.100:8000
```

> **小贴士：不知道NAS的IP？** 去路由器后台看，或者飞牛手机App首页也能看到。

登录之后，你会看到飞牛OS的桌面——

**有图有真相**（用文字脑补一下🤪）：
> 界面大概长这样：左边一列是功能菜单，中间是大桌面区域，底部有任务栏。跟我们平时用的Windows/Mac差不多，NAS也有自己的"桌面"。

### 第二步：在应用中心搜索OpenClaw

1. 点击左侧菜单的 **「应用中心」** 图标（像一个购物袋🛍️）
2. 在搜索框输入 **`openclaw`**（注意大小写无所谓）
3. 你会看到一个龙虾图标🦞的应用，没错就是它
4. 点击 **安装**，等几分钟

> **安装过程会怎样？** 飞牛会下载镜像、创建容器，你看到进度条在走就行了。喝杯水回来就好。

安装完成后，桌面上会多一个 OpenClaw 的图标。点它就能打开Web界面了。

## 1.2 装完后的第一件事

打开OpenClaw，你可能会被一堆术语吓到——

**Gateway、Model、Provider、Channel、Agent……** 别慌。

### 🛒 用"超市"来理解

把OpenClaw想象成一家**自助超市**：

| 术语 | 超市比喻 | 说人话 |
|------|----------|--------|
| **Gateway** | 超市大门🚪 | 所有请求都要从这里进出。客户端（比如你发消息）→ Gateway → 内部处理 → 响应出去 |
| **Model（模型）** | 超市的商品🍎 | 你需要的大模型，比如DeepSeek、GPT、Claude。OpenClaw本身不生产模型，它只是模型的搬运工 |
| **Channel（通道）** | 超市的收银台💳 | 消息怎么发送出去。比如你接入了Telegram、飞书、Discord，那就各是一个通道 |
| **Provider（供应商）** | 供货商🚛 | 谁提供模型给你调用。比如DeepSeek官方、硅基流动、或者你自己用Ollama部署的模型 |
| **Agent（智能体）** | 收银员/导购员🧑‍💼 | 真正干活的人。你配置了"xingzuo"这个Agent，它就知道用哪个模型、从哪接收消息 |

**一句话总结：**
> 用户通过 **通道** 发消息 → **Gateway** 统一接收 → 匹配到对应的 **Agent** → Agent调用 **Provider** 提供的 **Model** → 生成回复发回通道

是不是没那么吓人了？

### 那装完后我要做什么？

其实**不需要动任何配置就能用** —— 飞牛应用商店版自带了一套默认配置：

- Gateway 已经跑起来了（默认连到本地 127.0.0.1:37307）
- 默认模型是 deepseek/deepseek-v4-flash（性价比极高）
- 通道没配，所以暂时只能通过Web界面玩

如果你想马上跟它聊天，在Web界面找个"聊天"入口就行了。基本配置我们后面再调，先让它跑起来再说。

## 1.3 检查服务状态

安装完想知道它到底在没在跑？看这里：

### Web方式（可视化）

打开OpenClaw的Web管理页面，如果能正常显示一个仪表盘（Dashboard），上面写着网关状态、Agent数量这些信息，说明**一切正常**。

> **截图描述：** 仪表盘上有个表格，显示 OS 版本、Gateway 是否可达、Agent 数量、Task 数量。绿色状态就是好的。

### 命令行方式（逼格高一点）

如果你会用NAS的SSH或终端（飞牛OS的"控制台"也可以），执行：

```bash
openclaw status
```

会看到类似这样的信息：

```
OS            → linux 6.18.18-trim · node 22.18.0
Dashboard     → http://127.0.0.1:37307/app/trim-openclaw/default/
Channel       → stable (default)
Gateway       → local · reachable 132ms
Agents        → 1 active
```

看到 `reachable` 就是正常的。

### 启动失败怎么办？

常见问题：

| 现象 | 原因 | 解决 |
|------|------|------|
| `Gateway unreachable` | Gateway没启动 | 重启一下OpenClaw |
| 网页打不开 | 端口被占用 | 飞牛商店版一般不会，手动装的注意端口冲突 |
| 装完没反应 | 镜像下载中？网络慢 | 等几分钟刷新 |

如果还是不行，去飞牛NAS的支持群里问，或者看日志：

```bash
# 看OpenClaw的运行日志
tail -f /vol1/@apphome/trim.openclaw/data/home/.openclaw/logs/*.log
```

## 1.4 飞牛版的特殊坑

### 应用商店版 vs 手动安装版

飞牛应用商店里装的 OpenClaw 是**官方适配版**，优势是：

- ✅ 一键安装，省心
- ✅ 自动适配飞牛OS的环境变量
- ✅ 卸载干净，不会留垃圾文件

手动安装版（用 npm 或直接下载二进制）：
- ⚠️ 你需要自己配置环境变量和系统服务
- ⚠️ 卸载要自己清文件
- ✅ 版本更灵活，可以尝鲜

**建议小白直接用应用商店版。**

### ⚠️ 飞牛的 trimafs 文件系统

飞牛NAS的存储基于 **trimafs**，这东西最大的特点是——**快照和回收站很强大，但不要乱用 `rm -rf` 批量删文件！**

trimafs 的删除操作其实是在写元数据，如果你在一个大目录下 `rm -rf` 成千上万个文件，CPU 会飙高、系统会变卡。正确做法：

- 删除少量文件：用飞牛自带的文件管理器
- 批量删除：用 `trash` 命令代替 `rm`，或者走飞牛文件管理器的批量选择删除

### 配置文件到底在哪？

这应该是新手问得最多的问题了。记住这个路径：

```
/vol1/@apphome/trim.openclaw/data/home/.openclaw/openclaw.json
```

这就是 OpenClaw 的核心配置文件。**如果你想手动改配置（比如添加模型、调整通道），就是这个文件**。

当然，你也可以在Web管理界面里改，效果是一样的。

> **为什么是这个路径？** 飞牛的应用商店版把 OpenClaw 的数据放在 `/vol1/@apphome/` 下，这是飞牛规定应用数据存放的地方。`trim.openclaw` 是用户名，所以最终路径如上。
